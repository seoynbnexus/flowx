# Session Summary — FlowX Backend Test Suite

## Goal
Complete the test suite for FlowX backend (auth + campaigns + missing-transactions + concurrency + Phase 4 modules) while fixing bugs found along the way.

## Constraints & Preferences
- Real MySQL test DB, not mocked
- `vi.hoisted` + `vi.mock` for external client mocking (Razorpay, Google OAuth, crypto utils)
- `--no-file-parallelism` because tests share DB state
- All tests use actual Express app via supertest when testing routes
- `setup-mocks.js` exports shared mock handles (`mockGoogleVerifyIdToken`) so per-file tests can override per-call behavior via `mockResolvedValueOnce`

## Key Decisions
- Razorpay mocking moved from `setup-mocks.js` (global) to per-file `vi.hoisted` + `vi.mock` to avoid vitest factory hoisting issues and keep mock state isolated per test file
- Coin tests use `coinService.getAvailable(userId)` to discover monthly allowance dynamically instead of assuming wallet-only deduction
- OTP reading from `sendOtpEmail.mock.calls[0][1]` instead of mocking `generateOtp` — keeps crypto real, avoids per-file vi.mock for crypto utils
- `google-auth-library` mock refactored to export `mockGoogleVerifyIdToken` so per-file tests can customize with `mockResolvedValueOnce` instead of per-file `vi.mock('google-auth-library')`
- `subscription.completed` webhook now sets `status = 'canceled'` instead of `PLAN_STATUS.EXPIRED` (`'expired'`) because `user_subscriptions.status` ENUM only allows `'active','canceled','past_due','trialing'`
- For concurrency, used optimistic locking pattern (`UPDATE ... WHERE status = ? AND id = ?` + check `affectedRows`) for campaign status and publisher request transitions, and `SELECT ... FOR UPDATE` for wallet and payment order reads — avoids full table locks while preventing double-spend / double-process races
- Publishers rejecting/accepting requests now use guard functions that throw on status conflict, preventing races on the same request
- `deductCoins` in `ai.repository.js` now throws `ValidationError` if `affectedRows === 0` (previously silently no-op'd when balance insufficient)
- Analytics tests call controller handlers directly (controller → raw SQL) since they have no service layer
- AI `saveImage` tested via repo directly (avoids external `fetch` call)
- `verifyAccount` returns `mapAccountRow` with camelCase keys (`verificationStatus`) — test uses `verificationStatus`

## Critical Context
- `user_subscriptions.status` ENUM: `'active','canceled','past_due','trialing'` — value `'expired'` not allowed; webhook handler fixed to use `'canceled'`
- `createPackage()` in payment.repository.js requires `currency`, `taxRate`, `isActive`, `displayOrder` — passing `undefined` for any causes MySQL "Bind parameters must not contain undefined"
- `findOrderByRazorpayId` returns the **first** matching row — collisions cause "Order already processed" if mock IDs aren't unique across test files
- `getUserEntitlements` auto-assigns the `'free'` plan to users without a subscription — this gives `monthly_coins` allowance so wallet coins aren't touched until allowance depletes
- The `transaction()` helper uses `node:async_hooks` (`AsyncLocalStorage`) to bind queries — repository-level atomicity is verified in `atomicity.test.js`
- `SELECT ... FOR UPDATE` added in `ai.repository.js` (`findUserWalletCoinsForUpdate`), `payment.repository.js` (`findOrderByRazorpayIdForUpdate`) to prevent race conditions
- Optimistic locking added: `updateCampaignWithStatusGuard`, `updatePublisherRequestStatusWithGuard`, `updatePublisherRequestPublishedWithGuard` — all throw `ValidationError` on status conflict
- `setup-mocks.js` exports `mockGoogleVerifyIdToken` (shared `vi.fn()`) for per-test customization
- Running `npx vitest run --no-file-parallelism` yields **223 tests passing (29 files)** in ~6s
- MySQL DECIMAL columns (`monthly_price`, `yearly_price`) return as strings from `mysql2` — `mapPlan` now uses `Number()` to convert; TINYINT `is_active` returns as `1`/`0` — converted to boolean with `!!`
- `createPublisherRequests` in `campaign.repository.js` had a bug: 4 values per row but 5 SQL placeholders — fixed by removing `status` from INSERT (has DEFAULT `'pending'`)
- Seeded identity doc types: `aadhaar`, `drivers_license` (migration 013)
- `listAll` identity repository returns `{ documents: [...], total, page, limit }` (not `items`)
